# AutoGit

**中文菜单式 Git 助手：选一个任务，按提示完成，不用记一串 Git 和 SSH 命令。**

适合经常需要提交、上传、切分支、合并，却不想反复配置账号和密钥的使用者。支持多账号、每个项目独立选择身份，以及强推、reset、冲突恢复和 GitHub 协作。

当前版本 **0.5.0**，使用 **TypeScript / Node.js**，运行预编译的 JavaScript，**不需要 Python，也没有运行时 npm 依赖**。详细功能范围见 [功能与缺口台账](docs/capabilities.md)。

## 1. 环境要求

| 工具 | 要求 | 用途 |
| --- | --- | --- |
| [Node.js](https://nodejs.org/) | 22 或以上，附带 npm | 运行 AutoGit |
| [Git](https://git-scm.com/) | 2.28 或以上 | 本地版本管理与远程同步 |
| OpenSSH | 兼容的 `ssh`、`ssh-keygen` | SSH 密钥和认证；Windows 可使用 Git for Windows 提供的工具 |
| [GitHub CLI（gh）](https://cli.github.com/) | 可选 | GitHub 建库、公钥上传、PR、Issue、Release 等 API 功能 |
| Git LFS | 可选 | 使用 LFS 的项目 |

普通 Git 操作不需要 gh；GitHub API 登录与 SSH 公钥授权是两件事。

## 2. 安装和启动

### 安装本地 npm 包

在源码交付目录执行：

```sh
npm install -g ./artifacts/autogit-cn-0.5.0.tgz
autogit --version
autogit
```

也可以把包复制到其他机器，再用其实际路径安装。**目前没有发布到公共 npm registry**，不要直接安装 registry 上的同名包。`artifacts/` 是源码交付目录，不会随 npm 包安装到电脑上。

Windows PowerShell 可将路径写为 `.\artifacts\autogit-cn-0.5.0.tgz`。如果执行策略阻止 `.ps1` 启动脚本，使用 `npm.cmd` / `autogit.cmd` 即可。

安装或更新只替换程序代码，不删除独立的 AutoGit 账号资料。安装后用 `autogit --version` 核对实际运行的版本；多个 Node/npm 环境可能各有一份安装。

### 从源码启动

在本项目目录执行：

```sh
npm ci --ignore-scripts
npm run build
node dist/cli.js
```

开发依赖只用于编译和测试。已有构建时也可使用 Linux `./start.sh` 或 Windows `start.bat`；这两个启动器默认使用**启动器旁边的 `data/`**，保留调用者的工作目录。

### 不必每次进入项目目录

```sh
# 在任意目录指定项目
autogit --path "/你的项目路径"

# 同时指定固定的个人资料根
autogit --app-dir "/你的 AutoGit 文件夹" --path "/你的项目路径"
```

不传 `--path` 时优先恢复上次使用的项目；首次使用以当前目录为起点。进入后可用 **9** 切换目录，或用 **20** 从收藏和最近项目中选择。

## 3. 第一次使用：账号、密钥和授权

1. 启动后选择一个持久的个人 **AutoGit 文件夹**，默认是主目录下的 `AutoGit`。不要选在 `node_modules` 或 npx 缓存里。
2. 进入 **10 → 新建账号 / 生成密钥**，填写标签、提交姓名、邮箱和预期 GitHub 登录名。
3. 选择是否**记住认证**。选择记住会生成免口令私钥，之后不必每次输入密钥密码。
4. 将公钥授权给 GitHub：可复制账号详情中的公钥，手工添加到 [SSH keys](https://github.com/settings/keys)；也可在 **19 → SSH 公钥授权** 中通过已登录的 gh 上传所选 `.pub`。
5. 在账号管理中**绑定当前项目**；下载新的 SSH 项目时选好账号，下载成功后会绑定。
6. 测试账号并核对实际认证用户名。认证成功不代表对所有仓库都有写权限。

已有密钥可在账号管理中明确选择导入，软件只复制到自己的资料目录，不改外部原件。需要输入旧口令或设置口令时，由原生 `ssh-keygen` 在真实终端中处理；不要把口令或令牌粘进菜单。AutoGit 不保存 GitHub 明文密码。

### 多账号和三种传输方式

例如建立“个人”“公司”两个账号，分别绑定项目 A、B。从 AutoGit 发起的提交和托管 SSH 操作会选择对应署名与密钥；**不修改 Git 全局身份，绑定也不会自动影响 IDE 或原生 Git**。只改账号的显示标签会保留项目绑定，不需要重新配置每个项目；真正改变署名或预期登录身份时会说明受影响绑定。

在 **21 → 项目主机 / SSH alias / 代理** 中选择：

| 模式 | 使用什么配置 |
| --- | --- |
| 托管 SSH | AutoGit 账号中的密钥，适合软件内管理多账号 |
| 原生 SSH | 本机已有 SSH config，可配合明确的 Host alias、代理或跳板 |
| HTTPS | 外部 Git 凭据助手；软件内 SSH 账号不负责切换 HTTPS 登录身份 |

支持 GitHub.com、GitHub Enterprise 和普通 Git 服务。模式必须与实际远程 URL 一致；软件不会暗中改写远程地址。普通 Git 服务可以传输代码，但其专有 PR/Issue API 不属于 GitHub 功能。

## 4. 常用流程

### 下载已有项目

**2 → 输入 Git SSH/HTTPS 地址 → 选择父目录与新文件夹 → 选择账号/传输配置。**

可使用新文件夹，也可选择已有空目录。名称无效或目录非空时，只重选文件夹名称，不必重填仓库地址和父目录。下载失败会说明原因；下载成功而绑定失败时保留目录，不自动删除已下载内容。

### 把本地项目第一次上传

**3 → 新建 GitHub 仓库，或关联已有仓库 → 选择文件 → 填提交说明 → 上传。**

- 新建可选公开/私有。新仓库为空，不自动添加 README 或许可证；新初始化的本地分支使用 `main`。
- 自动建库需要 gh 的 API 登录，向导可引导登录/切换并核对账号。没有 gh 时，也可在 [GitHub 网页建库](https://github.com/new) 后关联地址。
- 已有远程可以保留，也可选择新的远程名称；不覆盖已有 `origin` 或悄悄改变拉取上游。
- 创建、关联、提交、上传分步报告。建库结果未知时先去 GitHub 核对，**不要直接重复建库**；已建成但关联失败时改用“关联已有仓库”。

### 每天保存和同步

| 想做什么 | 选择 |
| --- | --- |
| 选择文件、提交并上传 | **4** |
| 只提交到本地，不联网 | **12** |
| 本地已经提交，只需上传 | **14** |
| 获取远程更新 | **5** |
| 查看修改、暂存差异和历史 | **6** |
| 切换/新建分支、合并、解决冲突 | **7** |
| 临时收起或恢复未完成工作 | **11** |

已有暂存会明确显示，部分暂存不会被整个文件的其他修改替换。保存前，AutoGit 默认会把**超过 50 MiB 的全新未跟踪普通文件**加入项目根目录 `.gitignore`，文件仍保留在磁盘，不会自动暂存、删除或接入 Git LFS；50 MiB 正好不触发。规则写入后只有你明确选择 `.gitignore` 才会进入提交。已经跟踪、已暂存或部分暂存的文件不会被这个规则暗改；无法安全表示的特殊文件名只从本次提交候选中排除并提示。上传失败时保留本地提交，检查后重试上传即可，不必重复提交。

获取更新仅执行快进（`ff-only`）；工作区有改动或历史分叉时停止，不自动 stash、merge 或 rebase。新建、切换和跟踪分支可以携带 Git 能保留的未提交修改，只有真正会覆盖内容时由 Git 拒绝，不强制先 stash。两边各有独立首次提交时，可明确选择合并独立历史，说明影响后确认一次。合并不会自动上传。冲突后可在 **7 → 冲突中心** 或 **17** 处理，并按真实操作状态继续、跳过或中止；快捷模式下仅标记已编辑完成、正常继续以及 bisect 的 good/bad/skip 不再重复确认。

### 强推、撤销和恢复

- **15**：取消暂存、按指定来源还原文件、`reset --soft / --mixed / --hard`、`clean`。
- **16**：远程 URL 管理、远端分支删除、`force-with-lease` 或无条件 `--force`。
- **17**：revert、cherry-pick、rebase、bisect 和进行中的操作。revert/cherry-pick 支持单提交、提交列表和明确的 `A..B` 区间。
- **18**：历史详情、搜索、历史图、reflog 和创建恢复分支。

这些功能可以执行，不要求先 stash 或备份；会先展示目标与影响，再确认一次。普通上传失败不会自动变成强推。`hard reset` 会覆盖内容，`clean` 删除的未提交文件不能靠 reflog 找回。

## 5. 主菜单速查

| 编号 | 任务 | 编号 | 任务 |
| --- | --- | --- | --- |
| 1 | 首次配置 | 12 | 仅本地提交 |
| 2 | 下载已有项目 | 13 | 使用偏好、资料根、保管说明 |
| 3 | 首次上传 / 建库 / 关联 | 14 | 仅上传已有提交 |
| 4 | 保存修改并上传 | 15 | 撤销、还原、reset、clean |
| 5 | 获取远程更新 | 16 | 远程与强推工具 |
| 6 | 状态、差异和历史 | 17 | 操作中心 |
| 7 | 分支与合并 | 18 | 历史和 reflog 恢复 |
| 8 | 配置检查和诊断 | 19 | GitHub 仓库 / PR / Issue / Release |
| 9 | 切换项目 | 20 | 收藏与最近项目 |
| 10 | 账号与密钥 | 21 | 模板 / worktree / 子模块 / LFS / 主机 / 备份 |
| 11 | 收起 / 恢复工作 | 0 | 退出 |

默认是**快捷模式**，日常操作不重复确认；**13** 可改为详细模式。`:q` 返回，文件选择支持 `1,3` / `1 3`，`a` 全选。取消不会撤销前面已经完成的步骤。原生 Git/SSH 的输出可能是英文。

GitHub 协作还包括组织建库、fork、PR checkout/review/合并、Issue 编辑、标签和 Release 附件、协作者/团队权限。PR 本地分支重名时可换名、仅切换已有分支，或明确重建；仅切换不会自动更新到最新 PR。Release 附件保存重名时可换名或明确覆盖，覆盖前确认一次，下载失败不先删原文件。普通下载和新建本地 Tag 在快捷模式下直接执行，不套远程写入确认。权限、分支保护和 SSO 等仍按服务器规则执行。

## 6. 账号资料在哪里，怎么备份

```text
你选择的 AutoGit/
└── data/
    ├── profiles/       账号元数据、托管私钥和公钥
    ├── bindings.json   项目与账号的绑定
    ├── projects.json   项目收藏和最近使用
    ├── hosts.json      项目主机和传输配置
    ├── known_hosts     已确认的 SSH 主机指纹
    └── settings.json   偏好和上次项目
```

文件按需生成。npm 更新、卸载或清理 npx 缓存不会删除这份独立资料。

普通启动用一份**只含资料根路径**的 `location.json` 记住位置：Linux 为 `${XDG_CONFIG_HOME:-~/.config}/autogit/location.json`，Windows 为 `%APPDATA%\AutoGit\location.json`。显式 `--app-dir` 不读写这个指针；优先级是 **`--app-dir` > `AUTOGIT_DATA_DIR` > 位置指针 / 首次选择**。环境变量指向实际 `data`，参数指向它的父文件夹。

- **13 → 切换资料根**只切换位置，不复制或删除旧资料。
- **21 → 账号资料备份 / 恢复 / 搬迁**用于真正的备份与迁移；搬迁默认保留来源。
- 备份是 `manifest.json + files/` 目录，含托管密钥；SHA-256 检查完整性，**不提供加密**。
- gh 凭据由外部 gh 管理，不在 AutoGit 的资料或备份里；新机器需单独处理 gh 登录。
- 兼容原有 profiles/bindings schema 2、settings schema 1。项目移动后请明确映射旧路径到新路径，不按同名目录猜绑定。

**请勿分享或公开上传整个资料文件夹。**记住认证使用免口令密钥；如果泄露，应去平台删除对应公钥，再生成新密钥并重新绑定。只删除本地文件不能撤销远端权限。共用一份资料就是共用其中的账号，需要独立身份时使用不同资料根。

## 7. 常见问题

**明明绑定了账号，为什么还是认证失败？** 先检查实际远程 URL 与传输模式。HTTPS 使用外部凭据助手，不使用托管 SSH 密钥；SSH 还需公钥已授权、账号有仓库权限。可用 **8** 诊断。

**为什么 GitHub 能登录，SSH 仍不能上传？** gh API 登录不等于公钥已授权，公钥授权也不等于仓库写权限。组织 SSO 和分支保护同样可能限制操作。

**为什么拉取没有自动合并？** 普通获取更新只快进。历史分叉时，用 **7 / 17** 明确选择合并或变基；软件不会替你猜。

**上传失败，刚才的提交还在吗？** 在。选择 **14** 重试上传。若提示远端已成功但上游关联未完成，只需检查本地上游配置，不要重复建库或强推。

**生成 README、忽略规则会自动提交吗？** 不会。大文件规则会在菜单 **3 / 4 / 12** 的提交准备阶段自动追加，取消后续提交也会保留已写入的规则，但不会擅自暂存。若 `.gitignore` 不可写或子目录规则重新包含大文件，会说明原因并仅跳过对应大文件，其他文件仍可保存。停止跟踪只调整 index，不删除工作区原文件；忽略规则不能从已有历史中抹去内容。

**把程序文件夹搬走会丢账号吗？** npm 程序和个人资料是分开的；便携启动器则默认使用旁边的 `data/`。移动资料请用备份/搬迁工具，或显式指定新的 `--app-dir`。跨系统时可能需要重新选择 SSH 程序路径。

## 8. 项目结构与开发验证

```text
src/                 TypeScript 源码
tests-node/          Node 内置测试与隔离 fixture
scripts/             构建、临时目录和正式验收工具
docs/capabilities.md 完整功能台账与验收边界
.github/workflows/   跨平台 CI 配置
dist/                生成的运行文件
artifacts/           当前版本包与一套正式验收证据
.claude-tmp/         自动隔离的测试临时目录
start.sh / start.bat 便携启动器
```

```sh
npm run typecheck
npm test
npm run verify
```

`npm test` 会先构建，再运行全部测试。`npm run verify` 是正式交付入口：离线安装开发依赖、类型检查、全套测试、真实 CLI 交互、本地打包、tar 内容白名单与源码快照核对。首次运行须已通过 `npm ci --ignore-scripts` 准备好 npm 缓存，离线依赖不足时不会自动改用联网安装。

验收成功后，`artifacts/` 更新当前版本的 8 项正式文件：安装包、`release` JSON、`verification` 摘要、全套测试日志、类型检查、npm-ci、纯 JSON 的 npm-pack 记录和汇总 CLI 转录。测试临时目录成功后自动清理；失败的正式验收会显示保留的诊断位置，不把半套结果标为通过。

测试使用隔离 HOME、Git、gh、资料根与 npm 环境；以真实本地仓库/bare remote 和 fake gh 验证流程，不读取个人密钥，不连接真实 GitHub。npm 生命周期测试覆盖隔离安装、重装、卸载与离线执行后的资料保留。

**实际验收与适用范围分开记录**：Linux / Node 22 的结果见源码目录下 `artifacts/verification-0.5.0.txt` 和 `release-0.5.0.json`。CI 包含 Ubuntu/Windows × Node 22/24，但配置存在不等于全部已运行通过；Windows 原生终端/OpenSSH、Node 24、真实 GitHub/Enterprise、LFS 服务和 SSH 代理/跳板仍需分别实测。更多范围与限制见 [功能与缺口台账](docs/capabilities.md)。
